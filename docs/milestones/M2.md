# M2: Durability, resume and the long-run features

## Scope

Plan §8 M2 (revised) plus handoff §4.3: the multi-cycle supervisor, the hierarchical cycle-0 planner with rolling-wave expansion, durable `goal.md` / `plan.json` / `progress.md` / `notes.md` / `codemap.*`, the phase machine with atomic state, the lock, reconcile, `--detach`, `pause`/`resume`/`stop`, `status`/`logs`/`runs`/`diff`/`checkpoints`/`report`/`plan`, heartbeat, ntfy, `service install` (systemd first, then launchd), outage backoff, run budgets with the 24 h defaults and the wrap-up reserve, stuck signals with ladder rungs 1/5/6, the judge's next-move/drift/similarity uses, and the worker backend interface, lifecycle and fake worker.

## Design

| Module                                           | Responsibility                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/core/supervisor.ts`                         | One supervisor per run. Startup: lock → reconcile → resume the persisted phase. Loop: guard-pre (control, run limits, warn, wrap-up, goal hash) → milestone checks and checkpoints → rolling-wave expansion → select → cycle → guard-post (stuck signals, ladder, next-move judge). Ends with a status, a report, an ntfy push and an exit code (0/2/3/4). |
| `src/core/lock.ts`, `src/daemon/boot-id.ts`      | `lock` = `{pid, host, bootId, startedAt}`, created with `O_EXCL`. Stale when the pid is dead or the boot id changed; takeover renames the stale lock away first, so two contenders can't both win.                                                                                                                                                         |
| `src/core/heartbeat.ts`                          | `heartbeat.json` every 15 s (injectable interval). `status` reports stale after 2 min.                                                                                                                                                                                                                                                                     |
| `src/core/control.ts`                            | Watches `control.json` once a second; `stop-now` aborts the in-flight model call and commands via the run's AbortController.                                                                                                                                                                                                                               |
| `src/guard/ladder.ts`                            | Ordered rung objects: `retry_with_evidence`, `park`. Run-level `stop_and_ask` when nothing runnable remains or the no-progress timer fires. M3 inserts rungs 2–4 into the list.                                                                                                                                                                            |
| `src/judge/next-move.ts`                         | Builds the redacted summary, asks the 7-option question, logs pick vs rule; `steer` applies a pick only if above threshold, allowed and implemented.                                                                                                                                                                                                       |
| `src/core/milestones.ts`                         | Milestone checks on `lastGreen`, tag `omnexx/<runId>/<milestoneId>`, checkpoint record, notes consolidation at milestone boundaries.                                                                                                                                                                                                                       |
| `src/agent/describe.ts`                          | Cheap-model one-line purposes for new or changed files in the codemap (budget-gated).                                                                                                                                                                                                                                                                      |
| `src/core/report.ts`                             | `REPORT.md`: the 8 sections of plan §14.4, deterministic from state, plan and events (no model call).                                                                                                                                                                                                                                                      |
| `src/notify/ntfy.ts`                             | Allow-listed fields only, redacted, timeout, failures logged and never fatal.                                                                                                                                                                                                                                                                              |
| `src/daemon/{detach,systemd,launchd,service}.ts` | Detached supervisor; unit/plist generation and validation; linger check.                                                                                                                                                                                                                                                                                   |
| `src/workers/*`                                  | `WorkerBackend` types, harness-side lifecycle (isolated worktree, scrubbed env, push disabled, process-tree timeout, capture, ref-tamper check, flatten commits, candidate diff → same VERIFY/JUDGE), semaphore, persisted quota state.                                                                                                                    |
| `src/cli/commands/*`                             | `supervise` (hidden), `resume [--all]`, `pause`, `stop [--now]`, `status [--json]`, `logs [-f]`, `runs`, `diff [--since]`, `checkpoints`, `report`, `plan [--edit]`, `service`.                                                                                                                                                                            |

## Proof of acceptance

- Chaos: `test/chaos/chaos.test.ts` SIGKILLs a real supervisor child process at a random phase (seeded) `OMNEXX_CHAOS_ITERATIONS` times (20 in CI, 200 nightly), resumes, and checks every invariant from plan §7.2.
- Reboot: kill, change the injected boot id, run the same `resumeAll` entrypoint the unit file runs; assert the resumed phase and no repeated commits.
- Detach/heartbeat/pause/resume: `test/integration/detach.test.ts` with real processes.
- Goal edits, ntfy fields, 30-task scenario with 3 kills and a 10-minute outage, hierarchical plan, codemap, checkpoints and report, wrap-up, fake worker, impossible-task parking, oscillation, budget stop and resume, judge invariant: `test/integration/*.test.ts`.
- Units: `systemd-analyze verify` (ubuntu CI) and `plutil -lint` (macOS CI) on generated files.
